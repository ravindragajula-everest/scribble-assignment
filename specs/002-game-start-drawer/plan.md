# Implementation Plan: Game Start & Drawer Flow

**Branch**: `002-game-start-drawer` | **Date**: 2026-06-02 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/002-game-start-drawer/spec.md`

## Summary

Wire up the "Start Game" button so the host actually starts the game: a new backend
`POST /rooms/:code/start` endpoint transitions the room to "in_game", assigns the host as
drawer, and fixes the secret word to "rocket". The host navigates to the Game screen
immediately; non-host players auto-navigate via the existing 2-second polling when they
detect the status change. The Game screen shows the drawer's name to all players and the
secret word only to the drawer.

## Phase 0: Research

*See [research.md](research.md) for full findings.*

All unknowns resolved from codebase analysis. Key decisions:

| Decision | Rationale |
|----------|-----------|
| `word?` and `drawerParticipantId?` optional in `Room` and `RoomSnapshot` | Both absent in "lobby" status; optional fields keep existing lobby tests passing without changes |
| `startGame` does NOT use `withLoading` in RoomStore | Follows `fetchRoom()` pattern; error bubbles to LobbyPage local `startError` state — consistent with existing `refreshError` pattern |
| Backend verifies host identity (participantId === room.hostId) → 403 | Defence in depth; UI already enforces host-only but backend must not trust the client |
| Word fixed to `STARTER_WORDS[0]` = "rocket" | Deterministic per spec; no randomness |
| Non-host auto-navigate: add `room.status === "in_game"` to existing redirect `useEffect` | No new polling mechanism required; existing 2s interval calls `fetchRoom()` which updates state |
| New E2E file `game.spec.ts` | Keeps `lobby.spec.ts` focused on lobby; game screen scenarios are a distinct concern |

```ts
export interface Room {

  word?: string;                  // set to STARTER_WORDS[0] when game starts
  drawerParticipantId?: string;   // set to hostId when game starts

  updatedAt: string;

export interface RoomSnapshot {
  code: string;
  status: RoomStatus;
  participants: Participant[];
  availableWords: string[];
  roles: ParticipantRole[];
  isHost: boolean;
  word?: string;                  // present only when viewer === drawer && in_game
  drawerParticipantId?: string;   // present when in_game
}
```

### Backend Service Changes

**`backend/src/services/roomStore.ts`**:

```ts
// New function — returns discriminated union
export function startGame(code: string, participantId: string) {
  const room = rooms.get(code);
  if (!room) return { error: "not_found" } as const;
  if (room.status !== "lobby") return { error: "already_started" } as const;
  if (participantId !== room.hostId) return { error: "not_host" } as const;

  room.status = "in_game";
  room.word = STARTER_WORDS[0];           // "rocket"
  room.drawerParticipantId = room.hostId;
  room.updatedAt = now();
  rooms.set(code, room);
  return { room: cloneRoom(room) };
}

// Updated toRoomSnapshot — add word and drawerParticipantId
export function toRoomSnapshot(room: Room, viewerParticipantId?: string): RoomSnapshot {
  const isDrawer =
    room.status === "in_game" &&
    viewerParticipantId !== undefined &&
    viewerParticipantId === room.drawerParticipantId;

  return {
    code: room.code,
    status: room.status,
    participants: room.participants.map((p) => ({ ...p })),
    availableWords: listWords(),
    roles: [...STARTER_ROLES],
    isHost: viewerParticipantId === room.hostId,
    ...(room.status === "in_game" && { drawerParticipantId: room.drawerParticipantId }),
    ...(isDrawer && { word: room.word })
  };
}
```

**`backend/src/api/rooms.ts`** — add route:
```ts
router.post("/:code/start", (request, response, next) => {
  try {
    const { code } = roomCodeParamsSchema.parse(request.params);
    const { participantId } = startGameSchema.parse(request.body);
    const result = startGame(code.toUpperCase(), participantId);

    if ("error" in result) {
      if (result.error === "not_found") throw new HttpError(404, "Room not found");
      if (result.error === "already_started") throw new HttpError(409, "Game already started");
      throw new HttpError(403, "Only the host can start the game");
    }

    response.json({ room: toRoomSnapshot(result.room, participantId) });
  } catch (error) {
    next(error);
  }
});
```

```ts
async startGame() {
```

### Data Flow

```
Host clicks "Start Game" in LobbyPage
─────────────────────────────────────────────────────────
1. handleStartGame() → roomStore.startGame()
2.                    → api.startGame(code, participantId)
3.                      ← POST /rooms/:code/start {participantId}
4.                         Zod validates; startGame() checks status + host
5.                         room.status="in_game", word="rocket", drawerParticipantId=hostId
6.                      → 200 { room: { status:"in_game", word:"rocket", isHost:true } }
7. setRoomSnapshot() → room state updated
8. navigate("/game")

Non-host polling detects game start
─────────────────────────────────────────────────────────
9.  setInterval fires → fetchRoom() → GET /rooms/:code?participantId=guestId
10.                                    toRoomSnapshot(): isHost=false, no word
11.                                 → { room: { status:"in_game", drawerParticipantId:..., isHost:false } }
12. room.status = "in_game" in React state
13. redirect useEffect fires → navigate("/game", {replace:true})

GamePage renders
─────────────────────────────────────────────────────────
14. Guard: room !== null && room.status === "in_game" → render
15. drawerName = participants.find(p.id === drawerParticipantId).name
16. Host: Role="Drawer", word="rocket" visible, drawerName
17. Guest: Role="Guesser", drawerName, word NOT in snapshot
```

### Testing Strategy

**Unit tests** (extend `backend/tests/unit/roomStore.test.ts`):
- `startGame(code, hostId)` → status "in_game", word "rocket", drawerParticipantId = hostId
- `startGame(code, guestId)` → `{ error: "not_host" }`
- `startGame` on already-started room → `{ error: "already_started" }`
- `toRoomSnapshot(in_game_room, hostId)` → word: "rocket", drawerParticipantId present, isHost: true
- `toRoomSnapshot(in_game_room, guestId)` → no `word`, drawerParticipantId present, isHost: false
- `toRoomSnapshot(lobby_room, ...)` → no word, no drawerParticipantId (backward compat)

**Integration tests** (extend `backend/tests/integration/rooms.test.ts`):
- `POST /rooms/:code/start` with host → 200, room.status = "in_game"
- Host snapshot after start → room.word = "rocket"
- Guest snapshot after start → no `word` key in response
- `POST /rooms/:code/start` with guest participantId → 403
- `POST /rooms/:code/start` when already in_game → 409

**E2E tests** (`frontend/tests/e2e/game.spec.ts` — new file):
- Host clicks "Start Game" → navigates to `/game`, sees "rocket"
- Non-host auto-navigates to `/game` within 2 500 ms
- Non-host on `/game` does NOT see "rocket" anywhere
- Drawer name visible on `/game` for all players
- Host starts already-started game → error in Lobby (no navigation)
- Direct `/game` navigation before start → redirects to `/lobby`

### Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| `room.status` in redirect `useEffect` causes loop if GamePage also navigates | GamePage guard `room.status !== "in_game"` returns null; only one navigate fires |
| Non-host poll fires after navigate, re-triggering redirect | `{ replace: true }` prevents history stack growth; React Router idempotently handles same URL |
| `word` leaks to guesser if toRoomSnapshot logic wrong | Integration test explicitly asserts guestId snapshot has no `word` key |
