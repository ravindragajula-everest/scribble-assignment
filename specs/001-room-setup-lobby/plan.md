# Implementation Plan: Room Setup & Lobby

**Branch**: `001-room-setup-lobby` | **Date**: 2026-06-02 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/001-room-setup-lobby/spec.md`

## Summary

Add host tracking to rooms, enforce input validation on player names and room codes (both
frontend and backend), make the "Start Game" button host-only and 2-player-gated, and
replace the manual Refresh button with automatic 2-second polling. All work is additive
to existing routes and components — no existing endpoints or pages are replaced.

## Technical Context

**Language/Version**: TypeScript 5.6 — Node.js 18+ (backend), React 18 (frontend)
**Primary Dependencies**: Express 4.x, Zod 3.x, React 18, React Router 6.x, Vite 5.x, Vitest 3.x
**Storage**: In-memory only — `Map<string, Room>` in `backend/src/services/roomStore.ts`
**Testing**: Vitest 3.x (unit + integration, both packages); Playwright (E2E — new devDependency, justified below)
**Target Platform**: Node.js 18+ backend on localhost:3001; modern browser frontend on localhost:5173
**Project Type**: Web application — frontend + backend monorepo
**Performance Goals**: Lobby poll at exactly 2-second intervals; no other latency budget
**Constraints**: No WebSockets, no DB, no auth, no new runtime dependencies
**Scale/Scope**: Lab-scale — single room per session, handful of players

**Playwright justification** (Constitution Principle II): E2E tests covering Scenario 1
(two-browser polling) are non-negotiable per the constitution. Playwright is the only
dependency that can drive two simultaneous browser tabs. It is a devDependency only —
zero impact on the runtime bundle.

**`@axe-core/playwright` justification** (Constitution Principle V + Check Gate 5):
The constitution mandates WCAG 2.1 AA compliance and requires Playwright accessibility
assertions to show zero violations as a merge gate. `@axe-core/playwright` is the
standard integration between Playwright and the axe-core accessibility engine.
devDependency only — zero runtime impact.

## Phase 0: Research

*See [research.md](research.md) for full findings.*

All unknowns resolved from codebase analysis — no external research required.
Key decisions:

| Decision | Rationale |
|----------|-----------|
| `isHost: boolean` in snapshot (not raw `hostId`) | Uses the existing `viewerParticipantId` seam in `toRoomSnapshot()`; keeps host ID internal |
| Validate in Zod schemas with `.trim().min(1, message)` | Centralises validation; reuses the existing ZodError handler pathway |
| Surface Zod field message in errorHandler | One-line change to `router.ts`; makes all validation errors descriptive without per-route try/catch |
| Native `fetch` for integration tests (Node 18+) | No new dependency; `createApp()` is already exported and testable |
| Extract validation into `frontend/src/utils/validation.ts` | Pure functions → unit-testable without DOM or component rendering |
| `setInterval` + `clearInterval` in `useEffect` cleanup | Standard React interval pattern; cleanup on unmount satisfies FR-008 |
| Playwright for E2E | Only tool that can drive two simultaneous browser tabs; devDependency justified by Principle II |

## Phase 1: Design

### Backend State Model Changes

**`backend/src/models/game.ts`** — two additions, nothing removed:

```ts
// Room (internal — never sent to clients)
export interface Room {
  code: string;
  status: RoomStatus;
  participants: Participant[];
  hostId: string;          // NEW: participant ID of creator
  createdAt: string;
  updatedAt: string;
}

// RoomSnapshot (returned by all three endpoints)
export interface RoomSnapshot {
  code: string;
  status: RoomStatus;
  participants: Participant[];
  availableWords: string[];
  roles: ParticipantRole[];
  isHost: boolean;         // NEW: true when viewer === host
}
```

### Backend Service Changes

**`backend/src/services/roomStore.ts`**:

- `createRoom(playerName)`: set `room.hostId = participant.id` before storing
- `toRoomSnapshot(room, viewerParticipantId)`: replace `void viewerParticipantId` with
  `isHost: viewerParticipantId === room.hostId`

### Backend Schema Changes

**`backend/src/api/schemas.ts`**:

```ts
// playerName: was optional(), now required, trimmed, non-empty
export const createRoomSchema = z.object({
  playerName: z.string().trim().min(1, "Player name is required")
});

export const joinRoomSchema = z.object({
  playerName: z.string().trim().min(1, "Player name is required")
});

// code: add trim + min(1) so blank code returns 400 not 404
export const roomCodeParamsSchema = z.object({
  code: z.string().trim().min(1, "Room code is required")
});
```

**`backend/src/api/router.ts`** — one-line change to ZodError handler:

```ts
// Before:
response.status(400).json({ message: "Invalid request payload" });

// After:
const zodError = error as ZodError;
response.status(400).json({ message: zodError.issues[0]?.message ?? "Invalid request payload" });
```

### Frontend Utility — Validation

**`frontend/src/utils/validation.ts`** — pure functions, no React import:

```ts
export function validatePlayerName(name: string): string | null {
  return name.trim().length === 0 ? "Player name is required" : null;
}

export function validateRoomCode(code: string): string | null {
  return code.trim().length === 0 ? "Room code is required" : null;
}
```

**`frontend/src/pages/LobbyPage.tsx`** — polling + host-only button:

```ts
// Polling: replace manual refresh with setInterval
useEffect(() => {
  const id = setInterval(() => {
    roomStore.fetchRoom().catch(() => { /* silent — FR-008a */ });
  }, 2000);
  return () => clearInterval(id);
}, [roomStore]);

// Host-only "Start Game" button (replaces unconditional button):
{room.isHost && (
  <button
    className="button button--primary"
    disabled={room.participants.length < 2}
  >
    Start Game
  </button>

```

### Data Flow

```
CreateRoomPage                    backend/roomStore
──────────────────────────────────────────────────────
1. User submits valid name
2. validatePlayerName() → null (passes)
3. api.createRoom(trimmedName)
4.                           ← POST /api/rooms {playerName}
5.                              Zod trims, rejects blank → 400
6.                              createRoom(): assigns hostId = participant.id
7.                           → 201 {participantId, room: {isHost: true, ...}}
8. RoomStore.setRoomSession()
9. navigate("/lobby")

LobbyPage (polling loop every 2s)
──────────────────────────────────────────────────────
10. setInterval fires → roomStore.fetchRoom()
11.                          ← GET /api/rooms/:code?participantId=abc
12.                             toRoomSnapshot(): isHost = (abc === room.hostId)
13.                          → {room: {participants: [...], isHost: true/false}}
14. React re-renders list + button state

JoinRoomPage (second player)
──────────────────────────────────────────────────────
15. validatePlayerName() + validateRoomCode() → pass
16. api.joinRoom(code, name)
17.                          ← POST /api/rooms/:code/join {playerName}
18.                          → {participantId, room: {isHost: false, ...}}
19. navigate("/lobby") — no "Start Game" button rendered
```

### Testing Strategy

**Unit tests** (`vitest run` — no server, no browser):
- `backend/tests/unit/roomStore.test.ts`:
  - `createRoom()` sets `hostId` to first participant's ID
  - `toRoomSnapshot(room, creatorId)` returns `isHost: true`
  - `toRoomSnapshot(room, otherParticipantId)` returns `isHost: false`
  - `toRoomSnapshot(room, undefined)` returns `isHost: false`
- `backend/tests/unit/schemas.test.ts`:
  - `createRoomSchema.parse({playerName: ""})` throws ZodError with "Player name is required"
  - `createRoomSchema.parse({playerName: "  "})` throws ZodError with "Player name is required"
  - `createRoomSchema.parse({playerName: "  Alice  "})` succeeds, trims to "Alice"
- `frontend/tests/unit/validation.test.ts`:
  - `validatePlayerName("")` → "Player name is required"
  - `validatePlayerName("  ")` → "Player name is required"
  - `validatePlayerName("Alice")` → null
  - `validateRoomCode("")` → "Room code is required"
  - `validateRoomCode("ABCD")` → null

**Integration tests** (`vitest run` — real Express, native fetch):
- `backend/tests/integration/rooms.test.ts`:
  - POST /api/rooms with blank name → 400, message "Player name is required"
  - POST /api/rooms with valid name → 201, response.room.isHost === true
  - GET /api/rooms/:code?participantId={creatorId} → room.isHost === true
  - GET /api/rooms/:code?participantId={joinerId} → room.isHost === false
  - GET /api/rooms/:code (no participantId) → room.isHost === false
  - POST /api/rooms/:code/join blank name → 400
  - POST /api/rooms/:code/join valid → 200, room.isHost === false

**E2E tests** (Playwright — two real browser tabs):
- `frontend/tests/e2e/lobby.spec.ts`:
  - Tab A creates room, Tab B joins; Tab A sees B's name within 2 polling cycles
  - Tab A shows "Start Game" enabled after B joins; Tab B has no "Start Game"
  - Blank name on Create Room: error visible, no navigation
  - Blank code on Join Room: error visible, no navigation

### Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| `playerName` change from `optional()` to required in Zod breaks callers that omit the field | All callers (frontend) always send the field; backend-only change is safe for this codebase |
| Polling interval accumulates if `useEffect` runs more than once | `clearInterval` in cleanup function prevents leak; verified by E2E test |
| `room.isHost` is `false` when `participantId` not in query string | Expected behaviour per spec; GET /health remains unaffected |
| Playwright not yet installed | Justified devDependency per constitution; install in E2E task |
